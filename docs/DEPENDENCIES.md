## Selected for Sony ARW development

ExifTool inspection is isolated from caller configuration: doctor/version and metadata invocations use `-config ""`, the same fixed system `PATH`, and a recorded C locale without `HOME` or `EXIFTOOL_HOME`. The ImageMagick doctor probe uses the same recorded allowlisted environment as preparation, so hostile or accidental caller configuration/coder paths cannot alter readiness.

Hardening constraints bind readiness and correction claims to unambiguous evidence. Lensfun camera make/model must resolve to exactly one record before its mount can support a lens claim; duplicate normalized camera records are reported as ambiguous. RawTherapee camera aliases must resolve the captured make/model to at most one canonical key, including when keys differ only by case. `geki doctor` rejects a symlink in the RawTherapee executable or any ancestor before reading application metadata, keeping executable-version and bundle-resource evidence under one application root, and requires the identity-stable `RTv4_Large` ICC bytes to describe an RGB display profile. RAW source signature/hash checks around metadata extraction, before/after development, and at publication use non-blocking, no-symlink descriptors, require a stable regular-file identity and digest, and enforce the 1 GiB descriptor size limit before hashing.

RawTherapee 5.13 is installed from `brew install --cask rawtherapee`. The adapter calls `rawtherapee-cli` with the committed PP3 and requests a ZIP-compressed 16-bit TIFF, captures stdout/stderr, isolates settings/cache state, and records executable, application, PP3, output profile, complete bundled Lensfun database, source, and output fingerprints. RAW preparation does not accept PP3 or output-profile overrides; changing profile semantics requires a reviewed code, documentation, digest, and test change. The shipped PP3 must match its pinned SHA-256 before job creation, and the copied execution profile must retain that digest through manifest publication. Doctor uses the same identity requirement for RAW readiness. Camera-profile, output-profile, and Lensfun paths are derived from the selected executable's application bundle, and preparation does not accept unrelated resource overrides. The accepted output-profile fingerprint is checked around development and manifest publication, is carried into the manifest tool snapshot, and must match the TIFF's embedded profile. The adapter resolves the automatic camera-input choice in DCP, ICC, then camera-matrix order and records the selected profile plus the alias and camera-constants resources that govern that choice. Bundled camera constants use RawTherapee's JSON-with-comments syntax; GekiGrade strips comments with string awareness, parses the result, and requires a `camera_constants` object list before readiness. The launch-time version must be 5.13, and executable, camera-resource, and Lensfun fingerprints are checked around development. `geki doctor` treats missing, unreadable, or malformed application metadata as not ready and requires the profile directories, parseable alias map and camera constants, complete parseable Lensfun XML set, and other RAW dependencies before reporting readiness. RawTherapee is GPL-3.0; using a separately installed executable is suitable for this personal tool, while bundling or redistribution requires a dedicated GPL compliance review. Same-machine repeatability and one Sony ILCE-7RM5 compatibility path are confirmed. Camera color quality, paired JPEG fidelity, and broad lens/camera behavior remain unverified.

RawTherapee was preferred over darktable for the first adapter because a PP3 plus explicit CLI arguments is a smaller state surface. The official darktable CLI supports explicit XMP history but can also consult the library, configuration, styles, auto-presets, and last export configuration; isolating all of that is possible but broader. This is a reversible adapter choice, not a claim that RawTherapee has superior image quality. Primary references: [RawTherapee source/license](https://github.com/RawTherapee/RawTherapee), [RawTherapee color management](https://rawpedia.rawtherapee.com/Color_Management), [darktable CLI](https://docs.darktable.org/usermanual/development/en/special-topics/program-invocation/darktable-cli/), and [darktable isolated test environment](https://docs.darktable.org/usermanual/development/en/special-topics/test-environment/).

## Considered and deferred

- **OpenEXR intermediate:** stronger for unclipped float interchange, but the first JPEG slice benefits from a directly inspectable 16-bit ICC-tagged TIFF and matches RawTherapee output. Reconsider if real RAW evaluation shows TIFF range loss.
- **libvips/pyvips:** excellent streaming performance and LittleCMS support, but duplicates OIIO/Pillow roles for one-image-at-a-time Milestone 1. Its LGPL-2.1-or-later redistribution obligations also add packaging work. Reconsider for large-image memory pressure or batch export. [Official libvips overview](https://www.libvips.org/).
- **OpenCV:** not selected because its default image APIs do not provide the explicit ICC-managed boundary needed here, while its geometry/statistics would duplicate existing dependencies.
- **G'MIC:** not selected because the initial allowlist is small and analytic; its broad command/filter surface would increase validation and redistribution complexity.
- **darktable:** deferred as the alternative RAW adapter for the state-isolation reasons above.

## System profiles

The first slice uses `/System/Library/ColorSync/Profiles/ACESCG Linear.icc` and `/System/Library/ColorSync/Profiles/sRGB Profile.icc`. Their SHA-256 values are recorded per job. Apple profile files are not copied into this repository or redistributed. A future portable release needs independently redistributable, pinned profiles and a separate license decision.
